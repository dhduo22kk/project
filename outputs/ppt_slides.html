개발 배경

왜 만들었나

기존 ML 추천 결과를
상담사가 안 쓴다

추천 상품명과 고정 텍스트만 제공돼, 왜 이 상품인지·어떻게 말해야 하는지 맥락이 전혀 없었다. 결국 상담사들은 화면을 열지 않았다.

맥락 없는 고정 텍스트

녹취 데이터가 방치된다

수천 건의 통화 녹취 파일이 쌓여 있지만 청취·분석할 체계가 없어 그대로 사장된다. 고능률 상담사의 성공 대화가 노하우로 전파되지 않는다.

인사이트 전환 체계 부재

캠페인 대상 추출이
매번 수작업이다

기획자가 직접 조건을 설정하고 데이터를 필터링해 리스트를 만든다. 과거 성과 분석과 조건 검증 없이 감(感)에 의존하는 경우가 많다.

데이터 기반 근거 없음
세 가지를 하나의 AI로 연결한다

Grill Me 활용

설계 검토에 가장 많이 활용했다. HyDE, Dynamic Few-Shot, ReAct lite 아이디어도 Grill Me 대화 과정에서 도출됐다.

"설계 스트레스 테스트 → 아이디어 발굴"

도메인은 사람, 구현은 AI

보험 TM 채널의 실제 운영 방식, 상담사 워크플로우, 컴플라이언스 제약은 사람이 정의했다. 코드 구현과 리팩토링은 Claude가 담당했다.

"역할 분담의 명확화"

지속적 리팩토링

처음엔 if-else 분기로 에이전트인 척 하는 룰베이스로 시작했다. Grill Me를 통한 설계 재검토 후 LangGraph 실제 구현으로 고도화했다.

"룰베이스 → LangGraph StateGraph"

HyDE · Dynamic Few-Shot · ReAct

세 가지 모두 Grill Me 과정에서 나온 아이디어다. RAG 품질 문제를 논의하다 HyDE로 이어졌고, 노하우 전파 논의에서 Few-Shot이 나왔다.
