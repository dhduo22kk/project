왜 만들었나

기존 ML 추천 결과를
상담사가 안 쓴다

추천 상품명과 고정 텍스트만 제공돼, 왜 이 상품인지·어떻게 말해야 하는지 맥락이 전혀 없었다. 결국 상담사들은 화면을 열지 않았다.

맥락 없는 고정 텍스트

녹취 데이터가 방치된다

수천 건의 통화 녹취 파일이 쌓여 있지만 청취·분석할 체계가 없어 그대로 사장된다. 고능률 상담사의 성공 대화가 노하우로 전파되지 않는다.

인사이트 전환 체계 부재

캠페인 대상 추출이
매번 수작업이다

기획자가 직접 조건을 설정하고 데이터를 필터링해 리스트를 만든다. 과거 성과 분석과 조건 검증 없이 감(感)에 의존하는 경우가 많다.

데이터 기반 근거 없음
세 가지를 하나의 AI로 연결한다

Grill Me — 설계 스트레스 테스트

설계 결정마다 /grill-me로 스스로 검증했다. HyDE, Dynamic Few-Shot, ReAct 아이디어가 모두 이 과정에서 나왔다. "AI에게 시킨 것이 아닌, AI가 나에게 되묻게 하는 방식으로 설계를 정제했다."

"설계 검토 → 약점 발견 → 아이디어 도출"

도메인은 사람, 구현은 AI

보험 TM 채널의 운영 방식, 상담사 워크플로우, 컴플라이언스 제약은 사람이 정의했다. 코드 구현과 리팩토링은 Claude Code가 담당했다. 역할의 명확한 분담이 핵심이었다.

"비즈니스 요구사항을 대화로 풀어내고 방향은 직접 결정"

지속적 설계 고도화

처음엔 if-else 분기로 에이전트인 척 하는 룰베이스로 시작했다. Grill Me 재검토 후 LangGraph StateGraph 실제 구현으로 고도화, 단순 RAG를 HyDE + Dynamic Few-Shot으로 발전시켰다.

"룰베이스 → LangGraph CoT 에이전트"

HyDE · Dynamic Few-Shot · ReAct의 탄생

세 가지 모두 Grill Me 과정에서 나왔다. RAG 품질 논의 → HyDE, 노하우 전파 논의 → Dynamic Few-Shot, 불필요 검색 논의 → ReAct.

"AI와의 대화가 기술 설계를 바꿨다"
