Abstract

본 시스템은 영업 현장에 흩어져 있는 고객 이력, 계약·담보 현황, 콜센터 녹취, 상품 교육 자료를 멀티모달 AI Agent가 통합·분석하여, 상담사에게는 고객 맞춤 상담 스크립트를, 마케팅 담당자에게는 AI 기반 대상 리스트를 즉시 제공하는 지능화 시스템이다. 고능률 상담사의 성공 노하우를 녹취 데이터로부터 학습하여 전체 상담사에게 전달하는 구조는, 별도 파인튜닝 없이도 개인화된 수준 높은 스크립트 생성을 가능하게 한다. 완전 폐쇄망 환경에서 단일 서버로 동작하도록 설계하였으며, 기존 ML 추천 파이프라인의 결과를 계승하면서 상담과 마케팅 두 영역의 실질적 효율화를 동시에 달성한다.

Section 1

Executive Summary

본 프로젝트는 AI가 가장 잘 할 수 있는 것, 즉 분산된 정보를 통합하여 즉시 활용 가능한 형태로 변환하는 능력을 영업 현장에 적용한 시스템입니다. 상담사가 콜을 걸기 직전, 이 고객에게 지금 어떻게 접근해야 하는지를 AI가 판단하여 제시합니다. 마케팅 담당자는 대화형 인터페이스로 조건을 설정하고 대상 리스트를 즉시 추출합니다.

핵심 혁신은 두 가지입니다. 첫째, 여러 시스템에 분산된 고객 데이터(계약·담보·통화 이력), 콜센터 녹취, 상품 교육 자료, 기존 ML 추천 결과를 하나의 출력으로 통합합니다. 둘째, 고능률 상담사의 실제 성공 통화를 AI가 학습하여 전체 상담사에게 그 노하우를 전달합니다. 파인튜닝이나 별도 모델 학습 없이, 성공 사례를 동적으로 참조하는 방식(Dynamic Few-Shot)으로 경력에 무관하게 수준 높은 스크립트를 생성합니다.

본 시스템은 기존 ML 상품추천 배치를 대체하지 않습니다. 기존 추천 결과를 에이전트의 입력으로 계승하면서, 그 위에 AI Agent 레이어를 얹어 추천 결과를 상담사가 실제로 쓸 수 있는 형태로 변환하는 것이 목표입니다.

💡
한 문장 요약 — 전사 영업 데이터와 성공 콜 노하우를 통합하여, 상담사에게는 즉시 활용 가능한 맞춤 스크립트를, 마케팅 담당자에게는 AI 기반 대상 리스트를 제공하는 폐쇄망 완결형 AI Agent 시스템
Section 2

배경 및 개발 필요성

2.1 전사 DB 활용과 상담 성공률

전사 고객 데이터베이스를 영업에 효과적으로 활용하기 위해서는 개별 상담사의 상담 성공률을 높이는 것이 핵심입니다. 성공률을 높이려면 고객에게 맞는 상품을 추천하고, 그에 걸맞은 접근 방식을 제시해야 상담이 수월해집니다.

현재 이노스(장기TM 상담사 화면)에는 ML 기반 상품추천 시스템이 운영 중입니다. 고객 정보를 수집하여 자동 인수심사를 거친 뒤, ML 모델이 상품을 추천하고 그 결과를 상담사 화면에 상품명과 고정 텍스트로 표시합니다. 기술적으로는 완성된 시스템이지만, 상담사 입장에서는 "어떤 상품을 권할지"는 알아도 "이 고객에게 왜, 어떻게 말할지"는 여전히 개인의 경험에 의존해야 합니다.

2.2 AI로 해결할 수 있는 것

AI가 진정한 강점을 발휘하는 영역은 다양한 소스의 정보를 통합하여 맥락을 만들어내는 것입니다. 이 능력이 영업 현장에서 두 가지 구체적인 문제를 해결합니다.

  • 상담 준비 — 고객의 계약·담보·통화 이력, 과거 성공 콜 패턴, 상품 특징을 통합하면 "이 고객에게 지금 이 각도로 접근하라"는 맞춤 스크립트가 나옵니다. 분산된 시스템을 번갈아 조회하는 대신, 고객번호 하나로 모든 컨텍스트와 스크립트를 즉시 받습니다.
  • 마케팅 대상 추출 — 과거 마케팅 성과 데이터, 고객 활성도, 인구통계 조건을 통합하면 AI가 최적 대상을 자동 추출합니다. 담당자가 직접 SQL을 작성하거나 개발팀에 요청할 필요 없이, 대화형 폼으로 조건을 설정하고 리스트를 바로 내려받습니다.

2.3 녹취 데이터의 잠재 가치

콜센터에 축적된 녹취 데이터에는 고능률 상담사의 성공 패턴이 담겨 있습니다. 그러나 비정형 음성 데이터라는 이유로 조직 차원의 인사이트로 전환되지 못하고 방치되는 것이 현실입니다. 본 시스템은 이 녹취를 텍스트로 변환·분석·임베딩하여, 고능률 상담사의 접근 방식을 전체 상담사의 스크립트에 반영합니다. 경험이 쌓이지 않은 상담사도 성공 패턴에 기반한 전략으로 콜에 임할 수 있게 됩니다.

3.1 상담사 지원 흐름 — 콜 전 준비

4.2 처리 흐름 — 정형 데이터

Oracle 데이터베이스에 축적된 고객·계약·통화·마케팅 이력은 매일 자동으로 인프로세스 분석 데이터베이스에 동기화됩니다. 갱신 중에도 에이전트 쿼리가 중단되지 않도록 신규 데이터를 별도 공간에 적재한 뒤 원자적 교체 방식으로 반영합니다. 이후 에이전트는 Oracle에 접속하지 않고 로컬 분석 DB에서만 조회합니다.

4.3 처리 흐름 — 녹취 음성

녹취 파일은 서비스 개시 전 일괄 처리됩니다. 먼저 고정밀 한국어 음성 인식 모델이 음성을 텍스트로 변환하고, 즉시 개인정보 비식별화(2단계 마스킹)를 수행합니다. 이후 고객 프로필 정보와 결합한 형식으로 의미 벡터를 생성하여 저장합니다.

벡터 저장 시 임베딩 텍스트는 쿼리 시점과 동일한 형식으로 구성됩니다. 예를 들어 "52세 남성, TM 마케팅 유입, 뇌혈관 담보 미가입 — 통화 요약"과 같이 고객 프로필과 상담 요약을 결합한 형태입니다. 이를 통해 검색 쿼리와 저장 벡터가 동일한 의미 공간에 위치하여 유사도 검색 정확도를 높입니다.

신규 녹취가 추가되거나 일부 파일 처리가 실패하더라도 이미 처리된 건은 재처리하지 않고 이어서 진행하는 재개(resume) 방식으로 운영됩니다.

4.4 처리 흐름 — 상품 교육 자료

PDF·DOCX·PPTX 형식의 내부 문서는 형식별 전용 파서를 통해 마크다운 텍스트로 변환됩니다. 이미지를 포함한 문서의 경우 비전 언어 모델이 이미지 내 텍스트와 도식을 마크다운으로 변환한 뒤 합쳐 처리합니다. 변환된 내용은 의미 단위로 임베딩되어 상품 정보 벡터 DB에 저장됩니다.

Section 5

AI Agent 핵심 기술

5.1 자율성 제어 철학

에이전트가 모든 것을 자율적으로 결정하는 방식이 아닌, 결정론적 워크플로(데이터 수집·분류)와 AI 자율성(스크립트 생성)을 명확히 분리하는 설계 철학을 택했습니다. 고객 분류와 DB 조회는 결정론적으로 처리하여 정확성을 보장하고, 스크립트 생성 단계에서만 AI 자율성을 부여합니다.

5.2 8노드 워크플로우 파이프라인

상담사 지원 에이전트는 8개 노드로 구성된 워크플로우 파이프라인으로 구현됩니다. 매 요청마다 새로운 상태로 실행되며, 대화 세션 저장 없이 단발성으로 동작합니다.

Node 1
고객 분류
신규·미연결·이력 3분기 자동 결정
Node 2
데이터 조회
분석 DB 멀티 소스 동시 조회
Node 3
현황 포맷팅
계약·보장 현황 즉시 표시용 변환
Node 4
HyDE 생성
가상 성공 요약 생성 → RAG 검색 품질 향상
Node 5
RAG 검색
성공 콜·상품 문서 3단계 폴백 검색
Node 6
고객 분석
접근 각도·핵심 포인트 CoT 분석 (JSON)
Node 7*
추가 상품 조회
분석 결과에 따라 조건부 실행
Node 8
프롬프트 조립
Few-Shot + 분석결과 통합 → LLM 스트리밍

* Node 7은 분석 노드의 판단(상품 문서 추가 필요 여부)에 따라 조건부 실행됩니다. 하이라이트된 노드가 핵심 AI 처리 단계입니다.

5.3 HyDE — 검색 품질 향상

고객 프로필 텍스트("52세 남성, 뇌혈관 담보 미가입")와 성공 콜 요약("통화 중 담보 gap을 구체적으로 언급하며 체결") 사이에는 언어 표현의 간극이 존재합니다. 단순 유사도 검색으로는 관련성 높은 성공 콜을 찾기 어렵습니다.

HyDE(Hypothetical Document Embedding) 기법은 이 문제를 해결합니다. 검색 전 LLM이 먼저 "이 고객과 유사한 상황에서 성공한 통화의 가상 요약"을 생성하고, 그 가상 요약으로 벡터 검색을 수행합니다. 실제 성공 콜 요약과 동일한 표현 공간에서 검색이 이루어지므로 관련성 높은 사례를 효과적으로 탐색합니다. LLM 호출 실패 시 기본 프로필 텍스트로 자동 대체됩니다.

5.4 Dynamic Few-Shot — 고능률 노하우 전파

RAG로 검색된 성공 콜 케이스의 실제 상담 원문(비식별화 처리 완료)을 스크립트 생성 프롬프트의 예시로 동적 주입합니다. 파인튜닝이나 별도 모델 학습 없이, 현재 고객과 가장 유사한 상황의 고능률 상담사 어투·접근 방식을 LLM이 즉석에서 참고하여 스크립트를 생성합니다.

성공 콜 검색에는 3단계 폴백 전략을 적용하여 항상 유용한 케이스를 확보합니다.

  • 1순위 — 연결 성공 + 고객 태도 우호적 콜
  • 2순위 — 연결 성공 콜 (태도 무관)
  • 3순위 — 필터 없음 (최소한의 컨텍스트라도 확보)

벡터 DB 검색 결과가 없더라도 구조화 DB 조회 결과와 상품 문서 RAG만으로 스크립트 생성이 정상 동작합니다.

5.5 ReAct Lite — 필요한 곳에만 자율성

전체 파이프라인을 AI가 주도하는 완전 자율 에이전트 방식이 아닌, 분석 단계에서만 제한적인 자율성을 부여합니다. AI가 고객 분석 후 "추가 상품 문서 검색이 필요한가"를 판단하고, 필요하다고 판단한 경우에만 해당 조회 단계가 조건부로 실행됩니다. 불필요한 처리를 줄이고 파이프라인의 예측 가능성을 유지합니다.

5.6 CoT 2단계 체인 — 분석과 생성 분리

단일 AI 호출로 스크립트를 직접 생성하는 방식 대신, 분석과 생성을 2단계로 분리합니다.

  • 1단계 — 고객 분석 : 접근 각도(담보 보완·설계 팔로업·신상품 공략), 이 각도를 선택한 이유, 강조할 핵심 포인트를 구조화된 형식으로 도출합니다.
  • 2단계 — 스크립트 생성 : 1단계 분석 결과, 성공 콜 예시, 담보 현황, 상품 문서 내용, 이달 영업 포커스를 통합하여 최종 스크립트를 스트리밍으로 생성합니다.

중간 분석 결과가 명시적으로 존재하므로 AI의 추론 품질이 향상되며, 스크립트 생성 근거도 추적하기 용이합니다.

Section 6

개인정보 보호 설계

콜센터 녹취에는 고객 이름, 연락처, 주민번호 등 다양한 개인식별정보가 포함될 수 있습니다. 본 시스템은 음성 인식 직후 즉시 비식별화하는 2단계 마스킹 파이프라인을 통해 원본이 어디에도 저장되지 않도록 설계했습니다.

Step 1 — 정형 패턴
규칙 기반 즉시 치환
전화번호·주민번호·계좌번호·카드번호 등 패턴이 명확한 정형 개인정보를 정규식으로 즉시 치환. 확정적으로 식별 가능한 정보를 우선 제거.
Step 2 — 비정형 PII
LLM 마스킹 + 분석 통합
이름·주소 등 비정형 식별정보 마스킹과 감성·키워드·요약 분석을 단일 LLM 호출로 동시 수행. AI 호출 횟수 최소화.
원칙
원문 미보관
마스킹 완료 즉시 원본 폐기. 벡터 DB와 분석 DB 모두 컴플라이언스 승인 범위 내 비식별화 데이터만 저장.

분석 결과로 추출되는 정보는 고객 태도(우호적/비우호적), 상담 키워드(최대 5개), 상담 요약(2~3문장)입니다. 이를 토대로 생성된 임베딩 벡터는 비식별화된 요약 텍스트를 기반으로 하며, 원본 음성 파일과의 연결 고리는 처리 완료 후 폐기됩니다.

7.1 폐쇄망 배포 전략

서비스 서버는 인터넷이 완전 차단된 폐쇄망(Ubuntu, CUDA 12.4, GPU 40GB)에 위치합니다. 오픈망 PC(Windows, 관리자 권한 없음)에서 망간 파일 전송 시스템을 경유하여 반입합니다.

  • 패키지 번들 — Google Colab 스크립트로 의존성 전체를 tar.gz 형식으로 다운로드. 2GB 초과 파일은 자동 분할하여 전송 시스템 제한을 우회합니다.
  • LLM 모델 — Colab에서 GGUF 형식으로 다운로드·분할 후 반입. LLM 서빙 솔루션이 직접 임포트를 지원하여 별도 변환 과정이 없습니다.
  • 외부 서비스 의존성 제거 — 폐쇄망에서 HTTP 통신이 불가하므로 외부 프롬프트 관리 서비스 의존성을 완전히 제거하고, 모든 RAG 프롬프트를 한국어 도메인에 맞춰 직접 작성합니다.
